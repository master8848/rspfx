# Agent Note: Cert trust diagnostics and first-run warnings

Status: implemented

## Context

First-run `rspfx dev` in SharePoint mode (`https://localhost:4321` with `dev.tenantUrl` or `SPFX_SERVE_TENANT_DOMAIN` or `--tenant`) silently generated a self-signed cert in `~/.rspfx/certs` (`packages/manifest-server/src/index.ts:121` `ensureCertificates()` via `selfsigned` 825-day) and served workbench via `packages/dev-runtime/src/serve.ts:134` / `packages/plugin/src/vite.ts:334` / `packages/plugin/src/rsbuild.ts:362`, but `apps/cli/src/commands/doctor.ts:252` only checked `key.pem 0600` and reported `not generated yet` as `ok:true`, so users saw CORS, `NET::ERR_CERT_AUTHORITY_INVALID`, `Failed to fetch https://localhost:4321/temp/manifests.js`, or blank workbench and debugged code instead of cert trust (see `docs/getting-started.md:91` and `docs/roadblocks.md:24`).

## Decision

Extend `packages/manifest-server/src/index.ts:14` `TRUST_NOTES` with CORS symptom and `rspfx doctor` pointer, and export `getCertsDir()`, `CertStatus`/`getCertStatus()` (`X509Certificate` expiry <7d, SAN `::1`/hostname mismatch), `isCertTrusted()` (best-effort `security verify-cert -c cert.pem -p ssl` on darwin, `certutil -verify` on win32, `unknown` on linux), and `formatTrustInstructions()` (per-OS `security add-trusted-cert`/`certutil -addstore` command). Make `ensureCertificates()` warn on generation that browsers block `https://localhost:4321` until trusted. Update `apps/cli/src/commands/doctor.ts:28` `runDoctor()` to `await` three new checks (`cert exists` at `~/.rspfx/certs/cert.pem`, `cert valid >7d`, `cert trusted` via `isCertTrusted()`) plus existing `key.pem 0600` and `config/serve.json`, with `ok:false` and actionable detail when missing/expiring/untrusted. Update `packages/dev-runtime/src/serve.ts:134` to `getCertStatus()` before `ensureCertificates()` and warn if newly (re)generated or if `isCertTrusted()===false`/`unknown` with `formatTrustInstructions()` and `cert.pem.trust.txt` + CORS guidance. Mirror the warning in `apps/cli/src/commands/dev.ts:71` for the `vite`/`rsbuild` spawn path (workbench-only). Update fact homes per `docs/AGENTS.md`: `docs/getting-started.md#cert-trust` (per-OS commands, symptom, `rspfx doctor` verification), `docs/commands.md#rspfx-dev` and `docs/commands.md#rspfx-doctor` (new checks and `doctor --fix` regeneration), `docs/architecture.md#dev-mode` (HTTPS cert + warnings), `docs/internal-api.md#rspfx-manifest-server` (new exports), `packages/manifest-server/README.md` (API list).

## Consequences

`rspfx doctor` now reports 15 checks on a healthy project (4 cert checks) and fails with explicit `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain ~/.rspfx/certs/cert.pem` / `certutil -addstore -user Root` guidance when the cert is missing/expiring/untrusted, so first-run SharePoint CORS is diagnosed before code debugging. `rspfx dev` warns at startup in both rspack (`startServe`) and vite/rsbuild CLI paths, and `ensureCertificates()` logs the same on generation. `bun run test` 454/454 pass (including `packages/manifest-server/tests/manifest-server.test.ts:8` and `apps/cli/tests/doctor-clean.test.ts:1`); `bun run build` passes for `packages/*` and `apps/cli`.
