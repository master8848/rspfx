# Agent Note: Add SPFx version upgrade guide and expand compatibility matrix

Status: implemented

## Context

Users asked how to change SPFx version, whether they only change the number, that zero-install upgrades (no new `@microsoft/sp-*` installs) is a selling point, which RSPFX versions support which SPFx targets, what RSPFX handles per version (manifest schema, CDN URLs, loader expectations), how to migrate a Gulp/Heft project then upgrade, and Node.js requirements per SPFx target; these facts were scattered across `docs/compatibility.md#spfx-version-matrix` (`packages/core/src/versions.ts:13` one-line switch), `docs/migrating-from-gulp-heft.md`, and `docs/why-rspfx.md` with no step-by-step consumer guide and no explicit Node matrix or zero-install callout.

## Decision

Add `docs/upgrading-spfx-version.md` (tutorial) covering zero-install upgrades, step-by-step `spfxVersion` change in `vite.config.ts`/`rsbuild.config.ts`/`rspack.config.ts` via `rspfxVite`/`rspfxRsbuild`/`RspfxPlugin` (`packages/core/src/versions.ts:13` `SPFX_TARGETS`, `SPFX_DEFAULT_TARGET`), toolchain bump `bun update @mbsks/rspfx-plugin`, verification `rspfx doctor` (`apps/cli/src/commands/doctor.ts:159` `node >= 20`, `apps/cli/src/commands/doctor.ts:202` `sp-*` prefix check), what RSPFX handles automatically (`packages/manifest-generator/src/component-manifests.ts:80` `loaderConfig`, `packages/dev-runtime/src/release.ts:39` `cdnBasePath`/`HTTPS://SPCLIENTSIDEASSETLIBRARY/`, `packages/compiler-rspack/src/config.ts:234`/`packages/plugin/src/vite.ts:412`/`packages/plugin/src/rsbuild.ts:414` AMD wrapper, `packages/manifest-generator/src/manifests-js.ts` `manifests.js`, `packages/sppkg-builder/src/sppkg-builder.ts:105` ZIP layout, `packages/manifest-generator/src/sp-dependencies.ts` harvest + `reference/sp-component-ids.json` fallback), Node matrix (RSPFX 20+ for all targets vs official 18/20 or 20.19+/22 for `1.23`), and migrate-then-upgrade flow (`apps/cli/src/commands/migrate.ts:351` detection); expand `docs/compatibility.md` with full version table (`Target`/`Status`/`Official toolchain`/`Official Node`/`RSPFX Node`/`npmVersion` `spfxNpmVersion()`), `RSPFX and SPFx compatibility` line table, `Node.js requirements per SPFx target`, `What RSPFX handles automatically per SPFx version`, and `Zero-install upgrades`, link switching to `docs/upgrading-spfx-version.md`; link from `README.md`, `docs/migration-from-spfx.md`, `docs/migrating-from-gulp-heft.md`, `docs/why-rspfx.md`, `docs/getting-started.md`.

## Consequences

Consumers follow one file to change `spfxVersion` and `bun update` without installing new `@microsoft/sp-*` unless they import that runtime; `rspfx doctor` catches prefix drift; the matrix in `docs/compatibility.md` is the single home for SPFx targets (`packages/core/src/versions.ts:13`) linked from the tutorial and migration guides; Node 20+ is documented as normalized across `1.20`–`1.23`; future SPFx targets are added via `packages/core/src/versions.ts:13` per `docs/supporting-a-new-spfx-version.md` with automatic downstream derivations.
