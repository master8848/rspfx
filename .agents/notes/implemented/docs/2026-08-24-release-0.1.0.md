# Agent Note: Release 0.1.0 polish

Status: implemented

## Context

RSPFx 0.0.13 → 0.1.0 aggregates breaking changes across Phases 1–8 (FrameworkPreset `contributions`→`rspack`, branded `RspfxErrorCode`, `defineConfig<const T>` literal, `resolveConfig` `strictObject` dust rejection, `createRSPFX` instance replacing `registerPlugin`/`getPlugins`, `readProject` purity, kernel cache versioning, `rspfx migrate --to 0.1` codemod) without a single `CHANGELOG.md` history home or benchmarked baseline.

## Decision

Bump all 19 `packages/*` + `apps/cli` to `0.1.0` via `scripts/publish.mjs`, freeze `CHANGELOG.md ## [0.1.0] - 2026-08-24` with `### Breaking Changes`/`### Features`/`### Fixes` and `v0.1.0` tag linkage, capture `reference/baseline-0.1.0.json` and `reference/sizes-0.1.0.json` (`BENCH_RUNS=3` median, `cold start <2000ms` `recompile <300ms`), and polish `docs/internal-api.md`/`docs/commands.md`/`docs/architecture.md` to `reference` tier with fact homes (`docs/commands.md#environment-variables` for `RSPFX_LOG_LEVEL` etc) and `docs/performance.md` treemap.

## Consequences

Consumers upgrade via `pnpm add -D @mbsks/rspfx-cli@0.1.0` then `npx rspfx migrate --to 0.1 --dry-run` and `npx rspfx doctor --fix`; `pnpm publish:dry` verifies `CHANGELOG.md ## [0.1.0]` and git clean before `git tag -a v0.1.0` and `git push --follow-tags`; benchmarks and sizes are reproducible on second checkout within ±15% host variance.
