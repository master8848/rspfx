## 1. Your concern: "I saw JS code but the codebase is supposed to be TS-based"

**Verdict: no violations. Zero maintained-source JavaScript exists.**

Every `packages/*/src` and `apps/*/src` tree is 100% TypeScript. The JS you saw comes from five legitimate sources:

| Source | Example | Why it's fine |
|---|---|---|
| Build output (untracked) | `dist/*.js`, `examples/*/release/assets/*.js`, `*/sharepoint/solution/debug/**/ClientSideAssets/*.js`, `.rspfx/stats.json` | Generated by builds; **none are git-tracked** (`git ls-files` count: 0) |
| Test fixtures simulating SPFx output | `packages/compiler-rspack/tests/fixtures/basic/src/loc/en-us.js` (AMD locale module), svelte `generated/*.svelte.js` | Intentionally JS — they mimic what SPFx/the compiler produces |
| Standalone Node scripts | `scripts/*.mjs`, `bench/*.mjs` | Convention documented in AGENTS.md itself |
| Official-toolchain skeletons | `bench/skeletons/gulp/gulpfile.js` (CJS) | Gulp requires CJS; TS impossible |
| User-facing scaffold option | `rspfx new --language js` → generates `.js/.jsx` user projects (templates/src/index.ts:19,121) | Intentional product feature |

Repo hygiene is genuinely good here:
- ✅ No `allowJs` anywhere — tsc can never silently compile JS
- ✅ All relative imports carry explicit `.js` extensions (7 grep hits are template *strings* that generate extensionless imports inside user projects — intentional)
- ✅ rspfx-core has zero runtime dependencies (rule holds)
- ⚠️ But there is **no enforcement mechanism**: a stray `foo.js` dropped into any `src/` would be silently ignored by tsc — no error, no lint rule.

## 2. Your concern: "validation error messages need fixing"

52 `RspfxError` sites + ~35 raw `throw new Error()` sites inventoried. Message *content* quality is mostly good (offending value + file path included), but the **system around them is inconsistent**:

1. **Three error-code naming styles in the official registry** (`packages/diagnostics/src/codes.ts`):
   - SCREAMING_SNAKE majority: `COMPILE_FAILED`, `INVALID_OPTION`, `SPPKG_TRAVERSAL`…
   - PascalCase minority: `InvalidPackageConfig`, `InvalidManifestId`, `DuplicateManifestId`, `NoManifestsFound`, `MissingElementAsset`, `InvalidManifestJson`
   - Orphaned `E_` prefix: `E_BUILD_FAILED`, `E_MISSING_CAUSE` (used only by diagnostics' own tests — dead codes)
2. **Codes are never shown to users.** `apps/cli/src/cli.ts` `guard()` prints only `error.message`; the carefully assigned `code` field is invisible → dead weight for support/debugging.
3. **Internal package name leaks into user message**: `packages/core/src/config.ts:108` — `'rspfx: "name" is required in the bundler config (rspack.config.ts)'` (prefix style used nowhere else).
4. **Unprefixed console output**: `packages/manifest-generator/src/manifests-js.ts:25` logs without the `[rspfx]` prefix used everywhere else (12 logger/console sites audited).
5. **Docs drift on a validation behavior**: `reference/FORMATS.md:194` says auto-feature description "joins types"; code emits generic `'Component'` (sppkg-builder.ts:357–358).

### Security (from dedicated security auditor)

- **M-S1 [MEDIUM]** sppkg-builder.ts:153,161,252–257 — `feature.id` / manifest `id` interpolated into zip entry names without `toZipPath`/UUID validation; debug-dir write (`path.join(debugDir, ...entry.name.split('/'))`) allows `../../` escape → arbitrary file write relative to output dir on untrusted configs; also corrupts sppkgs. *Fix: validate ids as UUIDs or route all entry names through traversal guards.*
- **L-S1 [LOW]** `isAllowedOrigin` compares `h === '::1'` in **3 duplicated copies** (mock-api.ts:103, reload.ts:23, dev-server.ts:36), but WHATWG returns `[::1]` bracketed → IPv6 loopback never matches (gap in prior audit's fix). *Fix: strip brackets; dedupe into one shared helper.*
- **L-S2 [LOW]** mock-api POST needs no `X-RequestDigest` (only overrides do) → cross-site form POST can create junk items. *Fix: require digest or reject non-JSON content types.*
- **L-S3 [LOW]** compiler dev-server static middleware uses `fs.stat` (follows symlinks); sppkg glob correctly skips them. *Fix: lstat + skip.*
- **L-S4 [LOW]** templates/index.ts:268 — raw `tenantUrl` interpolated into single-quoted string in generated rspack.config.ts (`--tenant` is not charset-validated). *Fix: emit via `JSON.stringify(...)`.*
- **L-S5 [LOW]** browser.ts win32 path uses `cmd /c start` with URL containing unvalidated metacharacters. *Fix: rundll32 handler or charset validation.*
- **INFO** CORS `*` fallback when no Origin header (dev-only, GET/HEAD only); cert cache-hit doesn't re-chmod pre-existing loose key.pem; otherwise cert story clean (0600 atomic writes, printed-not-executed trust commands, zero committed certs repo-wide).
- **Supply chain clean**: no postinstall/preinstall anywhere, no eval/new Function in first-party source, mainstream deps.
- **Prior-audit (2026-08-19) regression check**: 15 of 16 claimed fixes verified still holding; `toZipPath` hardening is **partial** — elementManifests/resx covered, feature-id-derived names bypass it (see M-S1).
